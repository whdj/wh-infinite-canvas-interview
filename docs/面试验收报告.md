# AI 创作无限画布面试验收报告

## 1. 验收范围

- 项目：`WH Infinite Canvas`
- 仓库：`wh-infinite-canvas-interview`
- 验收基线：当前 `main` 分支
- 对照要求：`面试编码要求-智能无限画布.md` 的 P0、现场验收路径和技术追问
- 验证方式：代码路径核对、启动入口核对、持久化链路核对、静态语法检查。未配置第三方图片 API Key，因此没有把真实 API 生成结果当作本题 mock 验收证据。

## 2. 结论摘要

当前仓库是一个功能较完整的本地 AI 创作工作台，已经具备无限画布交互、节点和有向连接、真实 API 任务提交、输出节点、画布服务端保存等能力。

按照本题的严格 P0 标准，当前版本**不能判定为完整通过**。主要原因不是画布基础交互，而是题目限定的任务闭环与现有产品模型不完全相同：

1. 当前生成节点走真实 API 任务接口，不是无需 API Key 的本地 mock 服务。
2. 当前生成结果默认进入 `Output` 节点或生成节点的 `generatedOutputs`，不是自动创建为独立的图片节点。
3. 普通单节点失败主要通过错误提示处理，题目要求的确定性失败开关、保留任务快照和可重试闭环没有作为统一的面试模式提供。
4. 画布保存结构有节点、连接和视口，但画布记录本身没有明确的 `schemaVersion` 字段；工作流导出格式已有 `version: 1`，两者需要区分。

因此，现场应把已完成项和缺口主动分开说明，不要把真实 API 的 pending 状态描述成本题要求的 mock 任务通过。

## 4. 当前可执行的现场验收路径

### 4.1 启动准备

```bash
cd wh-infinite-canvas
python3 -m pip install -r requirements.txt
python3 main.py
```

浏览器打开 `http://127.0.0.1:3001`，进入画布管理并新建或打开一个 classic 画布。若使用 Windows，可运行仓库中的 `run.bat`。

现场不要提前打开一个已经摆好结果的画布；可以保留一个清空画布作为备用，但演示中的节点和连接应现场创建。

### 4.2 3～5 分钟演示顺序

1. 从工具栏创建图片、提示词和 `API生成` 节点。图片节点上传一张示例图片，提示词节点输入一句短提示词。
2. 在空白处点击，确认选择取消；按住鼠标中键平移；滚轮缩放；拖动一个节点，再次缩放，说明保存的是世界坐标而不是屏幕像素。
3. 从图片节点和提示词节点的输出端拖到生成节点输入端。生成节点中应出现图片引用和提示词预览；删除一条连接，再重新连接，展示有向关系可编辑。
4. 打开生成节点的比例或分辨率参数，说明参数保存在节点模型中。只有在已配置并确认可用的图片 API 时才演示真实生成；没有 API Key 时停在此处并明确说明本仓库当前未提供题目要求的本地 mock。
5. 如果已配置 API，演示真实任务的提交、pending 输出、完成后的 `Output` 节点和日志；不要将它表述为题目 P0 的独立图片结果节点。
6. 等保存状态完成后刷新页面，检查节点、节点位置、连接、视口和已有输出是否恢复。删除一个有连接的节点，确认相关连线一并消失。
7. 最后用一句话说明限制：当前版本的产品生成链路依赖真实 API，下一步会优先抽出本地 mock adapter、任务记录和独立图片结果节点，再补充确定性失败重试。

### 4.3 推荐现场表述

> 画布交互、节点模型、连接读取和服务端保存已经具备；当前仓库的生成层是面向真实 API 的产品实现。题目要求的是无密钥本地 mock，并要求结果自动成为独立图片节点，所以这两处我不会把现有 Output 结果冒充成完全通过。若继续实现，我会先把生成入口抽象成统一任务接口，再用本地 mock 实现 queued/running/succeeded/failed 和可重试记录，最后把结果资产创建成图片节点。

## 5. 技术追问准备

### 5.1 如果替换为后端任务服务，接口怎么设计？

建议回答为“提交、查询、取消、重试分离，任务状态由服务端持久化”。接口可以是：

```text
POST /api/generation-tasks
GET  /api/generation-tasks/{task_id}
POST /api/generation-tasks/{task_id}/cancel
POST /api/generation-tasks/{task_id}/retry
```

任务记录至少包括：`task_id`、`canvas_id`、`generator_node_id`、输入节点/资产引用快照、参数快照、`status`、错误信息、结果资产 ID、创建/开始/结束时间和 `idempotency_key`。状态机为 `queued -> running -> succeeded|failed|cancelled`，重试创建新的 attempt 或新的 task，不覆盖旧任务记录。

### 5.2 请求超时但服务端可能已接收，怎么避免重复生成？

客户端在提交前生成请求幂等键，服务端对 `(user_id, idempotency_key)` 建唯一约束，并在真正调用上游前落库。客户端超时后先按幂等键查询，不直接再次创建；如果上游支持幂等键，也把同一个键透传。若状态暂时未知，页面显示“查询中/待确认”，而不是把它当作失败重新提交。刷新时按任务 ID 查询，最终状态以服务端为准。

### 5.3 图片资源和画布节点如何保存、引用、删除？

生产设计中图片二进制放对象存储或本地资产目录，资产表保存 `asset_id`、URL、类型、尺寸、哈希和创建者；画布节点只保存 `asset_id`、显示信息和生成关系，任务结果保存结果资产 ID。删除节点只删除引用关系；资产采用软删除或引用计数，确认没有其他节点、日志或任务引用后再做垃圾回收。当前仓库的 classic 画布主要保存 URL/输出记录，适合本地工具，但还不是完整的资产表模型。

### 5.4 坐标和缩放怎么保证稳定？

画布状态使用世界坐标 `x/y`，视口保存平移量和缩放比例。屏幕点转换为世界点时使用：

```text
world = (screen - viewportOffset) / scale
```

拖动节点时把屏幕位移除以当前 `scale`；以鼠标为中心缩放时，先求鼠标对应的世界点，再调整视口偏移，使缩放前后该世界点仍落在同一屏幕位置。节点最终保存世界坐标，不保存渲染后的屏幕像素。

### 5.5 并发保存和数据升级怎么处理？

当前保存请求带 `base_updated_at`，服务端检测到旧版本时返回冲突，避免旧页面覆盖新页面。继续演进时会给画布增加 `schemaVersion`，读取时按版本执行迁移，保存时只写当前版本；迁移函数要幂等，并保留未知字段以便回滚。

## 6. 风险与后续优先级

### 当前风险

- 真实生成依赖 API 配置、网络和上游任务协议，无法作为无外部依赖的面试验收基础。
- `Output` 节点与题目要求的独立图片结果节点不同，现场容易被追问数据模型差异。
- 普通单节点失败缺少稳定的失败开关和任务历史，现场不能依赖随机 API 错误演示重试。
- 画布和工作流导出的版本字段不统一，未来数据结构升级需要显式迁移策略。

### 如果允许继续实现，优先级

1. 先抽象 `submitGenerationTask`，增加本地 mock adapter 和任务状态机。
2. 在任务记录中保存输入节点 ID、参数快照和结果资产 ID，增加确定性失败开关与重试。
3. 成功后创建独立图片节点并建立生成关系，保证结果不覆盖原图片且可连接下游。
4. 增加 `schemaVersion` 和刷新时 queued/running 任务的恢复或安全转失败策略。
5. 最后再补充任务历史、取消、导入导出和性能优化等 P1。
